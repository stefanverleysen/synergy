IMMEDIATE ACTION: Windows Touch Calibration Required

Before any further code debugging, all test machines need the Windows touchscreen calibration wizard:

  1. Open Control Panel → Tablet PC Settings
  2. Click Setup (under the Display tab)
  3. Follow the wizard — tap each touchscreen when prompted to identify which physical display it maps to
  4. Repeat for every machine in the test setup (server and all clients)

Why: Without calibration, Windows can map touch coordinates to the wrong monitor in multi-display setups. Synergy receives coordinates that don’t match any configured neighbor screen, so the switch silently fails. Stefan confirmed that running this wizard significantly improved touch-to-switch success rates.

This is likely the primary cause of the ~20% success rate on server↔client touches.

Regression Build 3: Client-to-Client Broken

Commit 9d05f96 introduced 3 changes that broke client-to-client touch switching:

Suspect 1: Hider Window Blocks All Client Touch Input

File: MSWindowsDesks.cpp:442-448

Build 3 added a TOUCH_SIGNATURE check that prevents the hider window from auto-hiding on touch-generated mouse moves. The hider stays on top, intercepting all input — WindowFromPoint() returns the hider instead of the real app window underneath.

case WM_MOUSEMOVE: {
  LPARAM extraInfo = GetMessageExtraInfo();
  if ((extraInfo & TOUCH_SIGNATURE_MASK) == TOUCH_SIGNATURE)
    break;  // hider stays visible — blocks everything
  // ... existing auto-hide code never reached
}

Suspect 2: Hook Relay-Mode Gate Change

File: MSWindowsHook.cpp:599-609

Changed touch event consumption from if (g_isPrimary) to if (g_isPrimary && g_mode == kHOOK_RELAY_EVENTS). Need to verify that DESKFLOW_MSG_TOUCH posted by the hook on clients has a consumer that isn’t gated by m_isPrimary.

// BUILD 2 (working):
if (g_isPrimary) {
  return 1;
}

// BUILD 3 (broken):
if (g_isPrimary && g_mode == kHOOK_RELAY_EVENTS) {
  return 1;
}

Suspect 3: Early Return Skips Activation

File: MSWindowsScreen.cpp:1980-1984

Added early return when the target window is already foreground — skips the click replay that triggers cross-machine focus switching.

if (foreground == root) {
  return;  // skips entire activation + click replay
}

Pre-existing ~20% Server↔Client Success Rate

Beyond the calibration wizard issue, there are code-level timing gates that compound to drop ~80% of touches:

Issue 1: m_isOnScreen gate drops touch events during transitions

Files: MSWindowsScreen.cpp:976 and :1472

Both DESKFLOW_MSG_TOUCH and onPointerInput handlers check if (m_isOnScreen) return. Touch events during the brief enter()/leave() state transitions get silently swallowed. Estimated drop: ~50%.

case DESKFLOW_MSG_TOUCH:
  if (!m_touchActivateScreen || m_isOnScreen)
    return true;  // silently swallowed

Issue 2: 500ms server cooldown blocks rapid touches

File: Server.cpp:785-789, constant: Server.h:489

kTouchSwitchCooldownTime = 0.5s blocks ALL screen transitions for 500ms after each touch switch. Additionally, the Stopwatch starts at time 0, so the first touch after startup is also blocked. Estimated drop: ~50% of remainder.

double elapsedTouchCooldown = m_touchSwitchCooldown.getTime();
if (elapsedTouchCooldown > 0.0 && elapsedTouchCooldown < 0.5) {
  return false;  // blocked for 500ms
}

Issue 3: 150ms debounce at screen level

File: MSWindowsScreen.h:368

kTouchDebounceTime = 0.15s — additional filtering before events reach the server. Combined with the 500ms cooldown, effective minimum touch interval is 500ms.

Issue 4: GetCursorPos() returns wrong position on clients

File: MSWindowsDesks.cpp:744

On clients, the cursor is parked off-screen. GetCursorPos() returns that parked position, not the actual touch point. Coordinates sent to the server are wrong. Flagged in PR review by Copilot, not yet fixed.

Combined math: 0.5 × 0.5 ≈ 25% — matches Abel’s ~20% report
